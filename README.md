# AnoWoW Item Editor

A fresh WPF desktop catalog. Charcoal panels, blue accents, and WoW rarity colors.

## Run

Double-click `START_EDITOR.bat`, or run `dotnet run --project AnoWowItemEditor.csproj -c Release` with the .NET 10 SDK installed.

Uses the previous editor's Windows DPAPI-encrypted MariaDB login from `%LOCALAPPDATA%/AnoCoreItemEditorStudio/mariadb-login.dat`. Credentials stay outside this repository. The original app and its data are preserved.

## Browsing and character previews

- Left navigation: Characters, Item catalog, Spell catalog, Proc catalog, and a separate Change history category.
- Sortable, virtualized item table with rarity-colored names, required levels, and IDs.
- Name or exact ID search; rarity, slot, type, required-level, and equipment-set filters. Advanced filters collapse to leave room for the tooltip.
- Resizable WoW-style tooltip panel, actual source labels, loading, empty, and connection failure states.
- Set names, all member pieces, and piece-count bonuses from server DB2 plus active MariaDB overrides. Click a set name to browse its pieces, or a piece to select it. Catalog previews show 0 equipped; character previews count saved equipped pieces and highlight matching thresholds (respecting specialization and skill restrictions).
- Armor/weapon types, bindings, requirements, item effects, sockets and socket bonuses, and sell prices. Fixed spell amounts (including references to another spell) are read from effect records.
- Catalogs and character previews are read-only. Reviewed History actions can change item-field overrides in `foreverclassic_hotfixes`; characters are never modified.
- Search the character list, load all owned item instances (equipment, bag/bank storage, mail, void storage, and other owned instances), and filter storage. Item stacks, duplicates, instance IDs, durability, enchantments, and socketed gem references remain distinct. Storage locations retain raw bag/slot information rather than guessing this custom server's bank slot boundaries.
- Enter a preview level from 1–60, then click **Apply level** (or press Enter) to recalculate the selected tooltip. Pending and applied levels are shown explicitly. Fixed-level items retain their base stats and say why. Reset immediately applies the selected character's saved level, or 60 in the catalog. The preview cannot save a level change. An online character's database snapshot may lag unsaved in-game changes.

The complete catalog uses installed server DB2 files in `C:/AnoCore/AnoCore-Server/data/dbc/enUS` for build `7.3.5.70450`. Valid registered MariaDB payloads replace DB2 values, including definitions verified in older builds. A payload's VerifiedBuild is provenance and need not equal its hotfix registration build. Latest registration status is determined by push ID for each table hash/record ID. A generic build-0 payload takes priority, otherwise the highest verified payload is selected. Native item identities are preserved even if the item name/details arrive later from SQL. DBCD obtains table definitions with GithubDBDProvider (internet access or its cache is required).

## Change history

The separate History category lists item-sparse database payloads and retained item snapshots from recorded activity. Filter Active/Inactive/All, search by name, exact ID or changed field, and optionally filter to items with recorded app activity. Rarity, slot, type, required-level range and equipment-set filters match the Item catalog. The active-override count in the footer opens this page.

Selecting a record shows two independent tooltips at the same applied preview level: original installed DB2 (or an explicitly identified preserved original) and current active item. For inactive entries the right pane shows the retained modified version, clearly marked inactive, rather than pretending it is live. Different tooltip lines are highlighted and a field table reports exact known differences. Item entries without an original definition are excluded from History, including Show removed entries and its displayed active/inactive counts. They remain in the Item catalog; no underlying data is removed. Original spell/set/calculation tables are loaded separately from current overrides.

Existing item activity is read from the Studio audit table and its backup mirror. New actions append events to both in one transaction; previous events remain unchanged. Recorded app events retain actor, recorded UTC time, provenance, and raw before/after snapshots. Database registrations alone establish neither authorship nor the original save time. The viewer distinguishes records with activity from unattributed database content.

The old count of 474 was incomplete: it excluded valid payloads whose verification build differed from their registration build. Correcting that check also recovers previously missing item names. Internal ingestion still includes server-supplied definitions, while the displayed History list and footer count now include only items with an available original. A visible override still does not establish who edited it.

**Revert** and **Reapply** open a review of the actual before/after item fields. A first revert removes the selected SQL sparse payload so the installed native definition takes effect; the exact modified payload stays in an immutable archive. Reapply restores it. An existing inactive SQL payload can also be activated, preserving its previous inactive state for reversal. Missing native originals, ambiguous multiple payload versions, and concurrent changes block unsafe actions. The app checks current rows, saved versions and installed definitions again when applying. Writes, snapshots and linked audit events commit together. Item identities, links and shared effects are retained. These actions cover item fields, not historical set/spell definitions. Reload the server and verify in game after a committed action.

**Remove from history** is available only for inactive entries and changes list visibility without deleting the retained payload or activity. **Show removed entries** lets you restore one to the list. Active entries cannot be hidden, including when an external change activates an entry after it was loaded. Reapply makes the entry visible again.

The first history action creates compatible audit/archive/visibility tables in `foreverclassic_hotfixes` and `anocore_studio_backup`, if needed. The existing Studio backup and protection records are preserved. Inactive previews retain item fields; referenced spell/set dependencies use current tables and are labelled accordingly.

## Spell and Proc catalogs

Search all installed spells plus active MariaDB overrides by name, exact spell/effect ID, description, or trigger. The Proc catalog includes item-effect definitions and spells with server proc rules or a proc aura mask. The Spell catalog includes all spells, including passive set bonuses such as Revenge (28844). Exact numeric ID searches bypass filters, and switching catalogs clears stale filters. Candidates still require suitability checks for the intended set/weapon. Catalog browsing is read-only; use Edit in a set to open an assigned bonus in its set context. Editors use filtered spell pickers, preselected at the current spell. The weapon picker still offers all spell candidates.

Details include resolved descriptions, raw spell/effect fields, cooldowns, proc/aura flags, server `spell_proc` rules when available, and existing set-bonus/item usage. Copy spell and item-effect IDs for reference. All difficulties are retained in the detail fields. Filter by school, effect type, aura type, existing set/item usage, server proc rules and description availability. Filters combine with search and can be cleared together. The same filters are available in editor spell pickers. Effect/aura types show readable names alongside their numeric IDs. Unknown/custom IDs stay explicit. The weapon spell/template picker additionally filters by Trigger (Use, Equip, Chance on hit and all other available values). Trigger filtering applies to configured templates; plain spells have an explicit no-template option. Reference tables are loaded independently from item-tooltip snapshots and refreshed together.

## Set creator

Open **Set creator** under Editors, or **Create new set…** in Gear designer.

1. Enter the new set name. Choose a destination equipment slot, search a base item and add a copy to the draft. Original items are always preserved. Slots are optional: sets can contain 2–17 bonus-counting pieces. Both ring/trinket slots are separate; two-handed main hands exclude off-hand selections. Shirt and tabard may be copied as outfit pieces but do not count toward the client's 17-member set array.
2. **Edit copy draft** opens the item editor in draft-only mode: Apply to set draft changes the pending copy, with no writes to the base. Optional bulk item/required levels apply to all pending copies. Names, stats, requirements and other fields can be edited per piece.
3. Add bonus spells, choose piece thresholds and optionally edit fixed bonus amounts privately for this set. Bonuses can also be added after creation using the existing set-bonus editor.
4. Inspect each piece's **World drops & review** page, then **Review & create set**. The set definition, new item IDs, appearance/effect links, bonus assignments/private spells, world loot rows, metadata and mirrored audit events save in one transaction. The created set opens in Gear designer for further edits to its duplicated items. No game items or sets are created merely by opening this screen.

Default world drops are **0.01% per piece** (one in 10,000 per eligible normal creature, before server rate multipliers). Each piece gets its own independent group-zero, quantity-one loot entry; existing loot entries are preserved. The preview shows the exact creature list, zones, level band and number of loot tables. Rates can be changed up to 1% in the creator, with an explicit refresh/review before saving. Boss-specific loot selection is future work.

The initial level policy is a visible design rule, not a claim of a native Blizzard drop formula: target creature level is the higher of required level and 75% of item level, rounded and capped at 60; eligible creature ranges must fit within target ±5 (capped at 1–60). Thus iLvl 80 uses level 55–60 creatures even if a base item has a low required level. All template spawns must resolve to known outdoor, expansion-zero map areas with a sufficiently high zone-level profile; the zone threshold uses the 75th percentile of normal spawned-creature levels. The installed MAPS v10 terrain area grid resolves zone IDs where SQL has zeroes. This resolves terrain areas, not indoor WMO overrides. Unknown locations are excluded. All users of a shared loot table must be eligible. Boss/elite ranks, NPCs, civilians, critters, extra-flagged creatures, scripted/scaling templates and instance spawns are excluded. Sources or world/map files changing after preview block stale creation. An iLvl 80 verification excludes Durotar and finds suitable high-level outdoor regions.

New set items retain their managed drop policy. Changing item or required level in the updated item editor recalculates eligible creature loot at the same chance; the review identifies the band change. Reverting/reapplying that edit restores both item fields and its exact loot distribution. Use the updated app for these items. **Item, set & proc edits** also contains the complete **NewSet** creation operation with group revert/reapply. Later item/bonus edits or owned item instances block an old creation revert from erasing subsequent work. Revert does not rewrite the selected base items. Game tests run in rolled-back transactions; reload server loot/client definitions and verify a created set in game after a real save.

## Gear designer

Open **Gear designer** under Editors. The selected catalog/character item is preselected as the candidate. Search the candidate list by name or exact ID and apply a preview level from 1–60.

- **Compare equipped gear:** choose a saved character and destination slot. Compare the candidate with the removed item(s), base stat totals/deltas and gained/lost set bonuses. Ring/trinket slots can be selected independently. A two-handed replacement removes both hand items; selecting an off-hand clears an incompatible two-handed main hand. Level/class-mask/skill failures and unique duplicates are flagged. This is hypothetical only; it never equips gear or updates character data. Missing calculations remain unresolved. Base candidate stats exclude enchants/gems; totals exclude proc and set-effect contributions. Talents, class proficiencies and custom equip rules still require in-game verification.
- **Item budget & balance:** inspect the ten stored stat allocations, their calculated values and percentage of the server stat-point basis. Compare with exact peers at the same item level, rarity, slot and subtype; chest/robe are equivalent. A ±20% deviation from peer median is a design guide, with small samples identified. This is not a universal power score or budget cap: sockets, armor, damage, procs and set bonuses require separate judgment. **Check draft balance** in the item editor also evaluates unsaved changes.
- **Set designer:** browse a set, select specific pieces or a piece count and apply the selection. See calculated combined base stats, rarity-colored set tooltip, bonus thresholds and next threshold. Missing definitions, repeated bonus spells and obvious slot conflicts are identified. Specialization/trait/skill/flag requirements are marked conditional. Open the selected piece or the set-bonus editor from this workspace, then refresh after saving.
- **Duplicate as new item:** available in the designer and item editor. Choose an existing source, edit the copy in a draft and review before saving. Saving allocates an unused item ID and new appearance/effect-link IDs in one transaction. Item identity, sparse fields, appearance mappings and effect assignments are copied; shared appearance/effect/spell definitions remain referenced. Source definitions are not edited. **Item, set & proc edits** records creation, supports revert/reapply and detects later edits/owned instances before allowing an old creation to be undone. Created items can be edited again. They have no installed native original and remain excluded from the legacy original-comparison History list; creation history remains available in the operation list. Reload the server and verify the spawned copy in game.

While the older app is running, use **START_DESIGNER_PREVIEW.bat** to open the separately built update in artifacts/set-review/. It uses the same database, so saves in either version remain real saves; stale edits are checked before writing. This launcher preserves the running app's binaries. The standard launcher builds the latest source after you close the older app.

## Item editor

Use **Items** under Editors, or double-click an item. Common fields cover name, rarity, item level, requirements, equipment slot, binding and set assignment. Subclass is a named dropdown that follows the item class (for example Weapon → Sword, subclass 7). The Stats tab accepts calculated amounts at the applied preview level and converts supported values to stored allocations. Advanced fields expose the remaining server fields; ID and build provenance stay fixed.

Side-by-side tooltips show the saved item and draft. **Show original** switches the left pane to the installed original, including its original spell/set tables, without changing the draft. It is disabled for items without an installed original. Reopening an already edited item loads its latest saved values and permits another edit; the original remains stable. Review & save records item and identity changes atomically with immutable snapshots, audit events and revert/reapply support in **Item, set & proc edits**. Concurrent changes block stale saves.

## Set-bonus and weapon-proc editors

Use **Set bonuses** or **Weapon procs** in the left Editors section. Search an existing set/weapon by name or exact ID. The current catalog selection is preselected when applicable.

- Set bonuses: add, change or remove bonus spells, edit piece thresholds and specialization/trait restrictions. Set name and membership stay unchanged. The two WoW-style tooltips show the rarity-colored set name, all member pieces and current/draft bonus text. Preview the equipped piece count using the settings panel. **Edit bonus values** edits supported fixed effect amounts for only the selected set: saving creates private spell/dependency records and client tooltip text, then repoints that bonus. Shared source spells stay unchanged. Scaling effects and known script-bound spells require dedicated support and are blocked.
- Weapon procs: add, replace or remove individual assignments without removing the weapon's other effects. Configure trigger, cooldown/category cooldown in milliseconds (-1 means spell default), charges, slot, category, specialization and condition IDs. Existing item effects can be selected as templates. Modified assignments receive their own effect IDs; shared definitions are never edited.
- Select a row, edit its settings and click **Apply row settings to draft**. Spell choice and row removal immediately update the draft. **Review & save** shows both configurations before an atomic save. Unsaved drafts prompt before being discarded. Reload the server after saving and verify in game.
- **Item, set & proc edits** under History shows these saved operations separately from item-field overrides. It retains both assignment versions and raw SQL/dependency snapshots. Revert/reapply append audit events and restore exact stored rows/IDs. Only inactive operations can be removed from the list; Show removed entries permits restoration.

Global spell/proc chance/PPM rules remain read-only. A candidate spell may require server-specific rules to behave as intended. Operation history marks edits as active until reverted; later edits can supersede them. Automatic restore blocks when current rows, registration history, native files or external shared references differ from the expected state, preserving newer work rather than guessing a merge. Historical spell descriptions use the current reference catalog. Private bonus spell records and tooltip blobs are retained in operation snapshots and restored with revert/reapply.
Base stats, armor, and weapon damage are calculated from the installed RandPropPoints, armor, damage, curve and socket-cost tables, with active hotfixes. Supported linear level curves use the preview level, subject to supported content tuning and saved fixed scaling levels. Fixed-level gear does not receive an artificial character-level multiplier. Original Dreadnaught Breastplate at item level 92 calculates to 1027 armor, 21 Strength, 43 Stamina, 13 defense, 12 dodge, and 20 hit rating.

`[scales]` remains for unsupported instance bonus lists, random properties, conditional/nonlinear scaling and spell-context calculations. Missing definitions are listed explicitly and never disappear from a character's inventory. `[client value]` marks unavailable maximum durability; owned items show their actual saved current durability. Enchants and gems are shown separately; their totals, character buffs/talents, rating percentages, and custom AnoCore behavior are not simulated. Values are a server-table base preview, not a claim of full client parity; an in-game comparison is still required for the custom server. Item icons remain future work.

Formula references: [TrinityCore Item.cpp](https://github.com/TrinityCore/TrinityCore/blob/master/src/server/game/Entities/Item/Item.cpp), [ItemTemplate.cpp](https://github.com/TrinityCore/TrinityCore/blob/master/src/server/game/Entities/Item/ItemTemplate.cpp), and [ItemEnchantmentMgr.cpp](https://github.com/TrinityCore/TrinityCore/blob/master/src/server/game/Entities/Item/ItemEnchantmentMgr.cpp). These upstream formulas do not establish parity with AnoCore's unavailable custom implementation.

The original Dreadnaught Breastplate (22416), set 523, is the reference example: nine pieces including the ring and bonuses at 2/4/6/8 pieces. Set lists and bonuses are loaded generically for all sets, without hardcoded Dreadnaught descriptions.

## Verification

`dotnet run --project AnoWowItemEditor.csproj -c Release -- --verify`

Loads real data and verifies catalog/set filters, member navigation, stat/armor calculations, fixed-level behavior, curve interpolation, spell descriptions, scaling fallbacks, and tooltip generation for every catalog item. Checks real character loading, preview levels, definition recovery, history filters and synchronized comparisons. Exercises revert/reapply, immutable snapshots, audit mirrors, conflict checks, inactive removal/restoration and active-removal rejection in a transaction that is rolled back. Loads and searches the complete Spell and Proc catalogs. The verification command creates missing history metadata tables but commits no item, registration or audit test changes. Renders `artifacts/catalog-preview.png`, `artifacts/dreadnaught-tooltip.png`, `artifacts/history-preview.png`, and (when characters exist) `artifacts/character-preview.png`. Results are in `artifacts/verification.json`, `artifacts/character-verification.json`, and `artifacts/history-verification.json`; failures use a nonzero exit code and `artifacts/verification-error.txt`. Additional results are in artifacts/action-reference-verification.json with spell/proc page renders. Set/proc save, revert, reapply, native removals, shared effect preservation and stale-save checks also run inside rolled-back transactions. Results are in artifacts/content-editor-verification.json; editor renders are artifacts/set-editor-preview.png and artifacts/proc-editor-preview.png. Item saves, synchronized identity edits, exact stat conversion, reopening and saving an edited item, original comparison, named subclasses, private Revenge 75→150, source preservation and private-spell revert/reapply are also verified in rolled-back transactions. See artifacts/item-bonus-verification.json, artifacts/item-editor-preview.png and artifacts/set-values-preview.png. Designer checks cover hand replacement, both ring/trinket choices, unique duplicates, stat deltas, unresolved modifiers, set threshold loss, peer budgets, named spell filters and trigger filtering. Clone creation, effect/appearance copying, source preservation, revert/reapply and later-edit conflicts are tested in rolled-back transactions. See artifacts/designer-verification.json and the gear-comparison, gear-budget and set-designer preview PNGs. Set creation, fresh IDs/membership, private bonus values, source preservation, terrain-derived high-level drops, group revert/reapply, managed level/drop edits and conflict rejection are additionally checked in rolled-back transactions. See artifacts/set-creator-verification.json and the set-creator-items, set-creator-bonuses and set-creator-drops preview PNGs. Generated artifacts are ignored by Git.

If an open app locks the normal build output, build a preview with `dotnet build -c Release -p:BaseOutputPath=artifacts/preview/`, then run `dotnet artifacts/preview/Release/net10.0-windows/AnoWowItemEditor.dll --verify`. Close and restart the normal app to load updates.

Readable spell type labels follow numeric definitions in [TrinityCore SharedDefines.h](https://github.com/TrinityCore/TrinityCore/blob/master/src/server/game/Miscellaneous/SharedDefines.h) and [SpellAuraDefines.h](https://github.com/TrinityCore/TrinityCore/blob/master/src/server/game/Spells/Auras/SpellAuraDefines.h). Terrain area-grid interpretation follows [TrinityCore GridMap.cpp](https://github.com/TrinityCore/TrinityCore/blob/master/src/server/game/Maps/GridMap.cpp) and the installed MAPS v10 headers. The default drop bands are the editor's documented policy, using this server's actual creature and map data.

## Safety, item filters and created-set maintenance

Use **START_DESIGNER_PREVIEW.bat** for the current separately built update. It preserves the binaries of an already running older app. Restart the preview to load new code.

- Missing calculation rows block item saves, copies, new sets and history restoration. The installed weapon-damage tables currently stop at item level 100. Unsupported scaling layouts remain blocked for editing. Tooltips distinguish missing server data from `[scales]`. See [SERVER_SAFETY.md](SERVER_SAFETY.md) for the crash investigation and its limits.
- Item browsing includes named subtype/material filters, including Cloth, Leather, Mail and Plate. The item editor can change material and named class restrictions independently; a Shaman version of Dreadnaught can use Mail and allow Shamans while preserving its appearance mapping.
- Stat type and amount changes enter the draft immediately. Review & save persists them; no separate Apply step is required. Invalid amounts disable saving.
- **Drop location** in Gear designer and the new-set drop page supports instance/raid selection followed by boss checkboxes and an explicit chance. Boss-only mode replaces that item's previous creature/world drops. Shared loot tables require selecting every affected template. Other items' loot rows remain intact. Item-drop edits have revert/reapply history, and explicit boss selections survive item-level edits.
- Aura type and Effect type in the spell picker accept typed name/ID searches. For example, type `modify crit`, then select the desired named aura to filter the spell list.
- **Edit bonus values** explains each supported value's meaning, unit and editor limit. Current and draft bonus text appear side by side. Unsupported parameters remain read-only; invalid/out-of-range values are rejected rather than silently clamped. Private spell edits and their history restores enforce these limits.
- **Modify created sets** reopens active sets created by this editor. Rename a set, remove members and add new copies of selected base items, then review and save. Removed items remain available with their existing drops and have their set assignment cleared. Added members receive fresh IDs and reviewed default 0.01% world drops. Set membership is limited to 2–17 equippable pieces, with valid bonus thresholds and a common allowed class. Save/discard membership drafts before using the linked item, bonus or drop editors. Membership edits appear as `SetMembers` in operation history and support conflict-checked revert/reapply.

The verification suite additionally writes `artifacts/safety-stats-bosses-verification.json` and renders the bonus-value explanation, aura search, Mail/stat draft, boss selector and Modify created sets windows. Membership additions/removals, rename, source preservation, unchanged removed-item loot, stale saves, undo/redo and bonus caps are tested in rolled-back transactions. Live custom server behavior still needs in-game verification.

DB2 schema downloads use DBCD's local DBDCache/ cache (ignored by Git), with up to three attempts for transient network failures in the shared table reader. The library refreshes cached definitions after one day. SQL hotfixes and installed calculation rows are still loaded and validated on saves.

## Equipment layouts for sets

Set creator, Modify created sets and Gear designer's Set designer now open a WoW-style equipment layout: armor/accessories down both sides of a character silhouette, weapons along the bottom, rarity-colored slot borders/names and a selected-item tooltip beside the layout. These are slot symbols and a silhouette; no live 3D model or extracted item artwork is included.

Click an occupied slot to inspect its actual tooltip. Double-click it to open the item editor. New set-creator copies and pending additions to created sets edit a draft; their base items remain unchanged. Save membership drafts before editing existing saved pieces. Clicking an empty slot in the creator/modifier opens its filtered base-item picker. The member tables, totals and bonus views remain available in adjacent tabs. Two ring/trinket positions are separate; a two-handed weapon reserves the off-hand. Extra or conflicting set pieces remain visible in an additional-pieces list rather than disappearing.

Equipment layout checks and a rendered example are written to artifacts/equipment-layout-verification.json and artifacts/equipment-layout-preview.png by --verify. These selection/layout checks make no game writes; the existing save/history integration checks roll their writes back.

Use --verify-equipment for the focused read-only equipment-layout and created-set footer checks without running save/history test transactions.

## Drop locations and complete-set review

Use **Edit drop locations…** beside the selected equipment-slot tooltip, or from a saved item's editor. Select an instance/raid, search its verified bosses and tick the destinations. Selections remain checked across searches and instances. **Currently saved drops** lists the item's direct creature loot rows and rates; review shows the proposed replacement before saving. Boss-only assignment replaces this item's direct creature/world drops. Other items and indirect reference/chest/vendor sources are not changed. Shared creature loot tables must be reviewed together. Saved changes have reversible operation history.

Set creator and Modify created sets also allow drop plans for pending copied pieces. These plans are saved with the new copies; they do not change the base items' loot. Unrecognized existing drop configurations require an explicit mode choice before replacement.

Open **Set preview & balance** in the sidebar, set designer or created-set modifier. Choose a saved character, designed set and preview level, then use **Apply level**. The equipment view simulates the whole set while retaining untouched equipment and inventory. Choose which finger, trinket or hand a single flexible piece replaces. Select slots for tooltips; expand the character base-stat comparison for current/with-set/delta totals. Equip restrictions and set threshold changes are available above the equipment view. This simulation does not write character data.

**Set balance review** compares the designed and reference sets, with common-slot comparison enabled by default. It shows base-stat differences, per-piece allocation against exact peers, unusual allocations, incompatible materials/classes and unreachable bonus thresholds. Bonus descriptions are listed separately. Enchants, gems, talents, buffs, proc DPS, bonus-effect stat totals and rating percentages are excluded. Unsupported instance modifiers remain unresolved. These are design checks; custom server behavior still needs later in-game verification.

The current isolated build is launched with **START_DESIGNER_PREVIEW.bat** from artifacts/set-review/. The full verification suite includes drop-plan/history rollback tests and set-review checks. Use `--verify-set-review` for focused read-only simulation, comparison and screen rendering; results are in artifacts/set-review-verification.json, full-set-character-preview.png and set-balance-review-preview.png.
